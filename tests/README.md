# Tests

Automated tests for the backend detection pipeline, plus manual test docs for the parts
that need a live LLM or the full extension to exercise.

## Running the automated suite

From the repo root, with the backend's dependencies installed (`pip install -r
backend/requirements.txt`, which includes `hypothesis`):

```bash
pytest tests/
```

Most of these are [Hypothesis](https://hypothesis.readthedocs.io/) property tests for
the lexical/semantic pre-classifier (see
[`specs/lexical-semantic-upgrade/design.md`](../specs/lexical-semantic-upgrade/design.md#testing-strategy)
for the full list of correctness properties they validate). They don't require Ollama
or any external API — everything under test is local, deterministic code.

| File | Covers |
|---|---|
| `conftest.py` | Shared fixtures: path setup so tests can import `backend`/`backend/ai`, Hypothesis strategies for generating knowledge-base corpora and prompts, mock Presidio results, config defaults, and an optional session-scoped FAISS index fixture |
| `test_lexical_engine.py` | Property 1 — IDF correctness with high-frequency term dampening |
| `test_semantic_engine.py` | Property 5 — semantic search score bounds and descending-order results |
| `test_pre_classifier_routing.py` | Property 6 — priority routing (secrets > PII > lexical verdict) |
| `test_hybrid_scoring.py` | Property 7 — hybrid score formula (`lexical_weight*tfidf + semantic_weight*semantic`) |
| `test_prompt_builder.py` | Property 9 — semantic-chunk vs. full-document context assembly |
| `test_integration_routing.py` | End-to-end `/api/scan` routing through Presidio → Pre-Classifier → (mocked) LLM → Policy Engine |
| `test_pipeline_e2e.py` | **Stub only** — intended to run every prompt under `samples/` through the full pipeline and diff against `samples/expected_results/`; not implemented, and `samples/` currently has no content to run against (see [`../samples/README.md`](../samples/README.md)) |

## Manual / live-dependency tests

These aren't run by `pytest` in CI-style automation because they need a live LLM
provider or are meant for human review:

- **`test_eci_smoke.py`** — run directly (`python tests/test_eci_smoke.py` from the repo
  root) with Ollama running locally (or a configured cloud provider). Sends a curated
  list of prompts through the real ECI classifier and prints results for a human to
  compare against "expected direction" — exact `reasoning` text varies between runs
  even at `temperature: 0`, so this isn't a pass/fail assertion suite.
- **`test_scenarios.md`** — a hand-maintained catalog of test prompts covering every
  rule in `backend/policy/rules.json`, every custom recognizer entity type, and every
  `backend/ai/schema.json` field that can influence a decision. Split into deterministic
  (Presidio + Policy only, exact-match expected) and ECI-dependent (LLM judgment,
  "expected direction" only) sections, plus known gaps worth a product decision. Use it
  as the reference when manually verifying a change to `rules.json`, a recognizer, or
  the ECI schema.
- **`PromptShield_TestSuite.xlsx`** — spreadsheet version of a broader test-case catalog
  (open directly in Excel/LibreOffice; not read or generated by any script in this repo).

## Notes

- Tests assume they're run from the repo root so `conftest.py`'s path setup can find
  `backend/` and `backend/ai/`.
- Property tests use `@settings(max_examples=200, deadline=None)` for anything involving
  model inference — expect these to take noticeably longer than a typical unit test.
- See [`../backend/ai/README.md`](../backend/ai/README.md#running-standalone) for the
  individual `pytest` invocations per module.
